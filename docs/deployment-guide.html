GitHub Pages deploy i DNS

Operativna uputa: kako se website objavljuje, koja je trenutačna konfiguracija domene i HTTPS-a, te kako po potrebi ručno re-deployati ili napraviti rollback.

Trenutačno stanje — produkcija

Cutover je gotov. Website je uživo na https://rotaryhealthprofessionals.org s uključenim HTTPS-om. Projektna adresa …github.io/website/ preusmjerava na domenu.
  • Repo rotary-healthcare-professionals/website je javan (GitHub Free plan); GitHub Pages i workflow su aktivni.
  • Build i objava idu automatski preko GitHub Actions na svaki commit u main.
  • Email organizacije i dalje ide preko Bluehosta (MX zapis mail.rotaryhealthprofessionals.org) — ne dirati dok se email ne preseli.

Konfiguracija (kako je posloženo)

  • Workflow: .github/workflows/deploy-pages.yml na main grani; gradi Astro i objavljuje na GitHub Pages.
  • Repo varijable (Settings → Secrets and variables → Actions → Variables):
    VarijablaVrijednost
    ENABLE_GITHUB_PAGEStrue
    PAGES_SITE_URLhttps://rotaryhealthprofessionals.org
    PAGES_BASE_PATHnamjerno se ne postavlja — prazno znači korijen domene (bez /website/)
  • Custom domena: u Settings → Pages postavljena je rotaryhealthprofessionals.org i uključen Enforce HTTPS.
  • CNAME datoteka: public/CNAME sadrži rotaryhealthprofessionals.org (build je kopira u objavu).
Ako se ikad ponovno postavlja custom domena, PAGES_BASE_PATH mora ostati prazan / nepostavljen. Postavljanje na / ili /website bi razbilo putanje na korijenskoj domeni.

Kako objaviti promjenu

  1. Automatski: svaki commit na main (uključujući izmjene iz Pages CMS-a) pokreće build i objavu — obično gotovo za 1–3 minute.
  2. Ručni re-deploy (ako treba iznova objaviti bez nove izmjene): Actions → Deploy to GitHub Pages → Run workflow → grana main. Ili iz terminala: gh workflow run deploy-pages.yml --ref main.
  3. Provjeri da su build i deploy zeleni, pa osvježi stranicu bez cachea (Ctrl+Shift+R).
GitHub Pages objavljuje zadnji uspješno završen deploy. Ako više izmjena ide istovremeno pa live izgleda zastarjelo, pokreni ručni re-deploy kako bi se objavilo aktualno stanje main.

Rollback

Website: ako neka izmjena razbije sajt, vrati prethodni commit na main (revert) — automatski se objavi ispravna verzija. GitHub čuva cijelu povijest.

DNS: krajnji rollback na stari hosting bio bi vraćanje apex A zapisa na 50.87.253.47 i micanje GitHub Pages zapisa. To više ne bi trebalo biti potrebno jer je cutover uspješan i stabilan; navedeno samo kao referenca.
